### Autopilot-stack

**You own the stack, never the landing. Hand the operator one linear Graphite stack to review and land.** **Autopilot-full** holds except for how verified work leaves. Each tick re-reads both playbooks from trunk, and this one wins where they differ.

1. **Run Autopilot-full's owners, minus the landing.** Owners report STACK-READY in place of merge-ready. They never restack onto another branch, trunk included, and never retarget, merge, close a PR, or arm auto-merge, because the root owns the chain's topology and the operator owns the landing. When an item depends on another, its owner branches from that item's branch, not from trunk.
2. **Give the topology one writer.** Owners push only their own branches, `git push --force-with-lease` after an ls-remote check, and report each tip and its intended parent. Only you restack or retarget a link, because two writers on one chain undo each other. Append each clean PR in dependency order and register it locally: `gt track -p <current-tip>`, then `gt submit --no-interactive --stack` from the tip. `gt submit` walks from trunk, so an owner on its own machine must never pull branches below its own into that walk; when instructed, it may set its bottom PR's base directly instead. An owner takes your push as its new base and lease, and on a conflict resolves its own slice for you to push.
3. **Absorb drift at the root.** Until landing starts, apply Autopilot-full step 5's test to each link and restack the chain (`gt restack`, `gt sync`) where it calls for one. Then apply the patch-id rule link by link, since a link's base is its parent.
4. **Deliver the chain, then keep your hands off it.** The chain is reviewable bottom-up in the Graphite UI, and each link carries its verdict in its PR. Once landing starts, nobody writes to the chain, because Graphite drains it and a second writer breaks a landing in flight. A mid-landing problem goes through you to the operator, and any fix waits for the operator's go.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

**Reply:** catch the operator up per the **ketchup** skill, with links to the stack root and tip, a one-line verdict per link, and anything parked or excluded with the reason.
